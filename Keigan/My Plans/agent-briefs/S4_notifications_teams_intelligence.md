1. **Stakeholders** CRUD (`/applications/{id}/stakeholders`; services via `subscribed_service_ids_json`, empty = all; channels; minimum priority; notification types; language; Teams channel destinations; distribution lists), test send, `/directory/users/search` (Graph in Entra mode; local users + existing stakeholders in local mode).
2. **Routing:** active stakeholders whose services intersect the affected services (or all), priority ≥ minimum, type subscribed, channel enabled; EN/JA templates per recipient (others fall back to EN).
3. **Outbox:** every message → `notification_delivery` → job `deliver_notification` (graph / smtp / simulated → status `simulated`); retries; `/outbox` list + detail with rendered HTML (Keigan admins).
4. **Contract methods:** `on_incident_detected` (email + create incident chat when priority meets a chat-subscribed stakeholder's threshold), `on_investigation_completed` (preliminary report email if `AUTO_SEND_PRELIMINARY_REPORT`, Adaptive Card in chat, set `incident.first_update_sent_at`), `send_communication`, `send_postmortem`, `post_to_incident_chat`, `notify_slo_burn_alert`, `create_incident_chat` (live: Graph chat + install app + store conversation reference; simulated: `teams_chat_identifier="simulated:<uuid>"` + mirror `conversation` (scope `teams_incident_chat`)), `poll_incident_chat` (live: Graph messages since last processed; simulated: new `teams_participant` messages in the mirror): mask PII; deterministic milestone phrases (`settings.teams_milestone_phrase_list`) → enqueue `generate_postmortem` + acknowledgement; questions to Keigan ("@Keigan", "Keigan, …") → `ChatService(session).answer_investigation_question` (guard with a fallback from the investigation summary) → reply; otherwise `teams_chat_digest` (fast model + mock) → `investigation_timeline_event` rows `chat_fact`; unprompted comment only if `should_comment`, confidence ≥ 0.7 and outside `TEAMS_UNPROMPTED_COMMENT_MINIMUM_INTERVAL_MINUTES`.
5. **Simulated Teams endpoints:** `GET /incidents/{incident_id}/teams-chat`, `POST /incidents/{incident_id}/teams-chat/messages` (simulated only; post as the current user, process immediately so Keigan replies). Bot endpoint handles `message` (mentions → answer) and `installationUpdate` / `conversationUpdate` (store reference); validate JWT; ignore unknown chats.
6. **Predictive intelligence** (job `run_predictive_analysis`): seasonal anomaly (robust baseline by hour-of-week over 4 weeks from `sli_measurement`; robust z > 3.5 for 3 consecutive samples), error-budget exhaustion forecast (`SloService(session).summarize_slos` guarded, else from measurements), saturation trend (CPU/memory/DTU via `query_metrics` over 7 days, `linear_trend`, time to 90 %), recurring incidents (same category/service ≥ 2 in 30 days), change risk (activity changes followed by error-rate increase). De-duplicate open signals, expire stale ones, fast-model narrative with numbers (+ mock), status changes, "investigate" → `InvestigationService(session).start_investigation(..., "manual", …)` guarded. Reports (job `send_intelligence_report`): proactive alert for high-confidence signals and weekly digest (health score 0–100, SLOs, signals, incidents, noise), stored + emailed to stakeholders subscribed to `intelligence_report`. Endpoints per `05` §9.
7. **Seed** (idempotent): run detectors over the seeded world (expect memory-leak forecast on claims-document-renderer, budget burn on chad-apim, latency creep on payment-api, recurring pattern if incidents exist); one weekly digest + one proactive report for CLMJP and CHAD; outbox rows for historical communications if S2's seed created them (guard); a simulated Teams chat (EN/JA SRE discussion, Keigan answers, chat facts) for the latest historical CLMJP incident (guard).
