## Backend (you own)
`controllers/chat_controller.py`, `dashboard_controller.py`, `administration_controller.py` (stubs); `services/chat_service.py`, `administration_service.py` (skeletons: keep contract methods), `services/dashboard_service.py` (new); prompts `investigation_chat.md`, `ai_chat_intent.md`, `ai_chat_query_generation.md` (few-shot per language: KQL for App Insights / Log Analytics tables, Elastic Query DSL, Splunk SPL; table/field catalogue per service type), `ai_chat_answer.md`; `ai/chat_ai_schemas.py`; `dtos/chat_dtos.py`, `dashboard_dtos.py`, `administration_dtos.py`.

1. **Keigan AI chat** (`/chat/conversations*`, `/chat/suggested-prompts`): conversations per user (scope `keigan_ai_chat`; `application_ids_json` ⊆ readable apps); `rate_limiter` (`CHAT_RATE_LIMIT_PER_MINUTE`). Per message: mask PII → intent (knowledge / data_count / data_pattern / mixed / out_of_scope) → resolve application(s) and service(s) among readable apps (names, types, topology via `KnowledgeService(session).get_current_topology_graph` guarded) → time range ("last 17 hours", "yesterday", "past 7 days"; pattern/chart without a time frame → `answerKind: "clarification"` with `clarificationOptions` 1 h / 24 h / 7 d / 30 d, resumed via `clarificationResponse`) → service's primary log source + language → generate query (deep model) → `validate_generated_query` → `telemetry_gateway.query_logs` (`purpose_parameters={"signal_kind":"generic"}`) → mask rows → answer (fast model): one human sentence + optional `chartSpecification` (shape in `05` §7) or table → persist with `messagePayload` incl. `queryDetails` and citations. Knowledge questions → `KnowledgeService.build_grounding_context` (guarded) with [K] citations. Audit every executed query (`ai.query.execute`). **Must work with `LLM_PROVIDER=mock`:** deterministic planner (regex intent + duration parsing + service-name matching + template KQL such as `AppRequests | where Success == false | summarize count()` and `… | summarize count() by bin(TimeGenerated, 1h)`) so "How many requests failed in the last 17 hours on claims-api?" and "Show me the pattern" return real numbers and charts from the simulator.
2. **Investigation chat** (`conversationScope: "investigation"`; contract `answer_investigation_question` used by S4's bot): context = RCA, hypotheses, evidence index, timeline, runbooks, topology. Real LLM: LangGraph ReAct agent (`gateway.chat_model(ModelTier.DEEP)`, `langgraph.prebuilt.create_react_agent`) with read-only tools `get_evidence(code)`, `search_knowledge(query)`, `run_log_query(service_name, question, lookback)` (same safe pipeline, scoped to the investigation's application), max 6 tool calls, `record_external_usage`. Mock: `generate_text` / deterministic summary. Suggested prompts ("Why not the database?", "What changed in the last hour?", "Draft a status update for executives", "Explain this to a new engineer").
3. **Home** (`/dashboard/home?applicationIds=`): greeting data, deterministic status sentence, KPI tiles (open incidents by priority; active alert groups + noise-reduction ratio; SLOs at risk via `summarize_slos` guarded; investigations 24 h + mean time to first update), application health cards (health ring %, worst budget remaining, 24 h availability sparkline, open incidents, latest predictive signal, component types), live incidents/investigations with progress, intelligence feed (`predictive_signal`), maintenance windows next 7 days, recent postmortems. Query entities directly; aggregate efficiently.
4. **Administration** (Keigan admins): `/administration/settings` (`safe_settings_for_display`, grouped, Keigan identity panel, integration statuses), connection tests (`servicenow`, `graph`, `llm` (tiny call or "mock mode"), `azure`, `email`), usage (tokens by day / application / feature, estimated cost via `LLM_PRICE_PER_MILLION_*`, average tokens per investigation), audit events (filters, pagination), jobs (stats by status/type, dead letters, retry), retention job `run_retention_cleanup` (per `03` §12), **simulation controls** `GET /administration/simulation/scenarios` (`SimulationService.list_scenarios`) and `POST /administration/simulation/scenarios/{scenario_key}` `{applicationId}` → `SimulationService(session).trigger_scenario` (local/dev/test only — how demos start a live incident).

Test the mock-mode chat questions above and a scenario trigger with curl.
