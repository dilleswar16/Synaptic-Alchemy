## Backend (you own)
`controllers/incident_controller.py`, `investigation_controller.py` (stubs); `services/incident_service.py`, `investigation_service.py`, `communication_service.py` (skeletons: keep contract methods/signatures), `services/evidence_service.py` (new); `ai/investigation_graph.py` (LangGraph), `ai/investigation_ai_schemas.py`; `integrations/servicenow_client.py` (live Table API, OAuth client credentials or basic via secret store; simulated → `ServiceNowSimulator`); `resources/catalogs/query_templates.yaml` (KQL / Elastic / SPL per service type × source kind, each with `signal_kind`, `evidence_category`, title; cover doc 06 §3.3); prompts `incident_triage`, `evidence_query_planner`, `hypothesis_application`, `hypothesis_dependencies`, `hypothesis_infrastructure`, `rca_synthesis`, `blast_radius_narrative`, `incident_communications`, `postmortem_report` (expert SRE prompts: calibration rubric, citation rules, blameless language); `dtos/incident_dtos.py`, `investigation_dtos.py`; seed `seed/investigation_seed.py` (`SEED_ORDER = 30`).

1. **ServiceNow poller** (job `poll_servicenow`): watermark per application in `platform_setting`; upsert incidents for the app's groups (read `servicenow_assignment_group`; S1 owns its API); deterministic priority mapping (impact × urgency) + guardrails; new incident → timeline event, `start_investigation`, enqueue `notify_incident_detected` (S4's handler); state sync.
2. **Incident room API** (filters, pagination, search by number/title, RBAC-scoped), detail, resolve (+ enqueue `generate_postmortem`), contract `create_servicenow_incident_from_alert_group` (used by S3).
3. **Engine** per doc 06 §3: triage → context (S1's `KnowledgeService.build_grounding_context` / `find_matching_runbooks`, guarded) + change events → evidence (templates over investigation + baseline windows; one `MaskingContext` per investigation; `condense_log_records`; signal strength; rule-outs; metric evidence; ranking + token trimming; optional planner loop with `validate_generated_query`) → three hypotheses in parallel → synthesis (leading hypothesis; What went wrong / Why / How to fix with citations; `remove_invalid_citations`; confidence cap; `classify_command_risk`; `neutralize_untrusted_links`) → blast radius (traversal over `service_dependency` + current topology + impacted SLOs via `SloService(session).summarize_slos` guarded + stakeholders) + narrative → communications (EN + JA). Live progress (`current_stage_name`, `progress_percent`, `stage_messages_json`). Evidence-only mode on `TokenBudgetExceededException` / `LlmUnavailableException`. Token totals + model names. Contract methods `start_investigation`, `attach_alerts_to_investigation`, `run_investigation`; then enqueue `notify_investigation_completed` (S4). Manual investigations, re-run, feedback, timeline, evidence detail.
4. **Communications and postmortems:** drafts (types/languages), edit, approve, send (`NotificationService(session).send_communication` — guard NotImplementedError: keep `approved`, return a clear message); postmortem (job `generate_postmortem`; incident + investigation + timeline incl. `chat_fact` events + Teams conversation messages + sent communications) → draft → edit → finalize → send (`NotificationService.send_postmortem`, guarded).
5. **Mock mode must look real:** mock factories that build plausible, evidence-citing content from the actual collected evidence and the matching `SCENARIO_CATALOG` entry (find the scenario window for the services/time): hypotheses with real evidence codes, fixes with `kubectl` / `az` commands using real resource names, code-change suggestions (file path + before/after), Japanese communications. With `LLM_PROVIDER=gemini` the same pipeline produces real analysis.
6. **Seed** (idempotent): for each `seed_context.historical_scenarios` window create a resolved incident (matching `external_incident_number`), **run the real evidence collection against the simulator for that window**, then hypotheses/synthesis/comms/postmortem via the mock factories, timeline, sent communications, final postmortem. Optionally `SimulationService(session).trigger_scenario(<CLMJP id>, "database_connection_pool_exhaustion")` so a live incident appears on next start (guarded).

Verify a full investigation end to end in mock mode (trigger a scenario or start one manually) and inspect stored evidence.
