# CHAD Known Errors & Exception Reference

## fundapis — `GlobalExceptionHandler` (`au.com.metlife.channel.exception.GlobalExceptionHandler`)

| Exception / Log String | Business Meaning | Root Cause | HTTP Code | SRE Action |
| :--- | :--- | :--- | :--- | :--- |
| `CosmosException` (statusCode=404) | The document looked up does not exist in Cosmos DB | A read by ID on `FundRequest` or `MemberProfile` found no document | `404` | Confirm the UUID/ID was correctly written in a prior POST. Check the `FundRequest` or `MemberProfile` container in Azure Portal → Cosmos DB account `cdb14470aepr0101` → Data Explorer. Not a pod issue. |
| `CosmosException` (statusCode≠404) | Cosmos DB operation failed | Cosmos 429 (RU exhaustion), 503 (Cosmos service unavailable), throttling, network partition | `500` | Open Azure Portal → Cosmos DB account `cdb14470aepr0101` → Monitoring → Metrics → filter `Total Requests` by status 429 or 503. For 429: scale RU/s on the affected container (`FundRequest` or `MemberProfile`) via Data Explorer. For 503 or timeout: check [Azure service health](https://azure.status.microsoft/). Do NOT restart pods; the fault is external. |
| `XSDFileNameException` | The XSD file for the requested `fundCode` does not exist in the schema directory | New fund code added without deploying the corresponding XSD file under `schemas/` | `400` | Deploy the missing XSD file under `fundapis/src/main/resources/schemas/` and redeploy `fundapis`. Schema files are bundled at build time — not a runtime pod error. |
| `XMLValidationException` | Posted XML does not conform to the fund's XSD schema | Malformed XML from the partner fund system, or schema mismatch after a schema update | `400` | Return the `ProblemDetails` error body (title: "Input Validation Error") to the partner fund IT team. Verify `fundCode` is being normalised to lowercase — the XSD lookup is case-sensitive. Not a pod issue. |
| `BusinessValidationException` | Business rule violated (e.g. invalid Income Protection cover combination for REIS) | Specific fund business rule failed during `businessValidationService.validateBusinessRules()` | `400` | Return `List<BusinessValidationErrorResponse>` body to caller. Not a pod issue. |
| `MemberNotFoundException` (fundapis) | Member with given ID not found | Member UUID not in `FundRequest` or `MemberProfile` Cosmos container | `404` | Confirm the member was previously posted via `POST /b2bservice/v1/schemes/{fundCode}/member`. Use Azure Portal → `cdb14470aepr0101` → Data Explorer → `FundRequest` container to query by document ID. Not a pod issue. |
| `ResourceNotFoundException` (fundapis) | A requested resource is absent | General not-found condition outside of member lookup | `404` | Search Elastic APM or run `kubectl logs -n chad deploy/chad-fundapis --since=1h \| grep "Resource not found"` and correlate the `X-CHAD-Request-ID` to identify which endpoint triggered this. Return 404 to the caller. Not a pod issue. |
| `IllegalArgumentException` | Invalid input parameter supplied | Bad request parameter value passed to a service method | `400` | Return `ProblemDetails` (title: "Bad Request") to caller. Not a pod issue. |
| `Exception` (catch-all, fundapis) | Unexpected error | Any unhandled exception not matched by a more specific `@ExceptionHandler` | `500` | Run `kubectl logs -n chad deploy/chad-fundapis --since=1h \| grep "Unexpected error occurred"` for the full stack trace. If Cosmos SDK: check `cdb14470aepr0101` in Azure Portal. If JAXB/XML processing: inspect the request payload. If `NullPointerException`: file a bug. |
| `log.error("Unexpected error occurred: {}", ex.getMessage(), ex)` | Catch-all log for all unhandled exceptions | Any uncaught `Exception` | — | Same as the catch-all row above — retrieve stack trace from pod logs. |
| `log.error("Cosmos DB error occurred: Status={}, Message={}")` | Cosmos DB fault — emitted before mapping to HTTP response | Any Cosmos SDK exception reaching the GlobalExceptionHandler | — | Correlate the logged `Status=` value: 429 → RU exhaustion (scale RU in Azure Portal → `cdb14470aepr0101` → Data Explorer); 503 → Cosmos service issue (check Azure status page); 401 → Cosmos key may have been rotated (verify `azure-cosmos-key` secret in Key Vault `kyv14470aepr0101`). Do NOT restart pod. |

## fundsso — Inline Error Handling (`FundIntegrationController` + service classes)

> **Note:** `fundsso` has **no `@ControllerAdvice` / `GlobalExceptionHandler`**. All error handling is inline `try/catch` in `FundIntegrationController.java` and called service classes (`SSOUtils`, `MemberProfileService`). Uncaught exceptions fall through to Spring Boot's default error handler and return `500`.

| Log String / Error Condition | Business Meaning | Root Cause | HTTP Code | SRE Action |
| :--- | :--- | :--- | :--- | :--- |
| `log.error("Member information not found for ID: {}", ...)` | Member ID not found in `fundapis` | `ssoUtils.fetchMemberInfo()` returned null/empty — `fundapis` returned 404 for this member+scheme | `404` | Return 404 to APIM caller. Confirm the member was previously submitted via `POST /b2bservice/v1/schemes/{fundCode}/member`. Not a `fundsso` pod issue. |
| `log.error("Reference value not returned from PingFederate")` | SSO flow broken — PingFederate did not return a `referenceValue` | PingFederate Reference ID Adaptor `RefIDChadAU` at `https://auth.asia.metlife.com/ext/ref/dropoff` returned empty/null reference | `500` | Check `https://auth.asia.metlife.com` is reachable. If reachable but failing, verify PingFederate credentials `ping-referanceid-uname` and `ping-referanceid-pwd` in Key Vault `kyv14470aepr0101` have not expired. Escalate to MetLife IAM/CIAM team if credentials are current. Do NOT restart `fundsso` pod. |
| `log.error("Error processing member information", e)` | Unhandled exception in the SSO request handler | Any unexpected exception in `FundIntegrationController` — `fundapis` unreachable, Cosmos error, or PingFederate HTTPS failure | `500` | Run `kubectl logs -n chad deploy/chad-fundsso --since=1h \| grep "Error processing member information"` for full stack trace. (1) If stack trace shows `fundapis` call failure: check `kubectl get pods -n chad -l app=chad-fundapis`. (2) If PingFederate SSL/connection error: check `https://auth.asia.metlife.com`. (3) If NullPointerException: file a bug. |
| `log.error("Error saving member profile to fundapis for fundCode: {}", fundCode, e)` | `MemberProfileService` could not save a member profile to `fundapis` | `fundapis` `POST /b2bservice/v1/schemes/{fundCode}/member/profile` returned non-2xx or threw | `500` | Run `kubectl get pods -n chad -l app=chad-fundapis -o wide`. If pods are not Ready: `kubectl rollout restart deployment/chad-fundapis -n chad`. If Running, check `kubectl logs -n chad deploy/chad-fundapis --since=30m \| grep -i error` for the root cause. |
| `log.error("Error getting member profile from fundapis for fundCode: {}, uuid: {}", fundCode, uuid, e)` | `MemberProfileService` could not retrieve a member profile from `fundapis` | `fundapis` `GET /b2bservice/v1/schemes/{fundCode}/member/profile/{uuid}` returned non-2xx or threw | `500` | Same as above — check `chad-fundapis` pod health and pod logs. |
| `log.error("Error fetching member info", e)` | `SSOUtils.fetchMemberInfo()` failed | Exception when calling `fundapis` to retrieve member info before PingFederate drop-off | — (propagates to controller catch-all as `500`) | Check `chad-fundapis` pod: `kubectl get pods -n chad -l app=chad-fundapis`. If `fundapis` is healthy, inspect the `fundCode` and member ID values being passed — invalid values cause `fundapis` to return 400 or 404. |

## APIM-Level Errors (returned before reaching any Spring Boot service)

| APIM Error Code | HTTP Status | Condition | SRE Action |
| :--- | :--- | :--- | :--- |
| `IP_NOT_ALLOWED` | `403` | Caller IP not in the APIM IP allowlist | Add partner IP to the APIM policy allowlist via the `14470_apim_deployment.yml` pipeline. Do NOT restart pods — the request never reached them. |
| `IPV6_NOT_SUPPORTED` | `403` | IPv6 source address detected | Partner must use IPv4. Do NOT restart pods. |
| `PAYLOAD_TOO_LARGE` | `413` | Request body > 5 MB or `Transfer-Encoding: chunked` | Reduce payload size on the caller side. Do NOT restart pods. |
| `QUOTA_EXCEEDED` | `429` | IP exceeded 1000 calls/hour or subscription exceeded call quota | Partner is sending too many requests. Check for runaway retry loops on the partner fund side. Do NOT restart pods. |
| `Unauthorized` (APIM validate-jwt) | `401` | Bearer JWT missing, expired, wrong audience, or wrong issuer | The Azure AD token has expired or was obtained for the wrong application registration. Do NOT restart pods — the request never reached them. Caller must re-authenticate against Azure AD tenant `ca56a4a5-e300-406a-98ff-7e36a0baac5b`, requesting audience `api://bc5fa7ea-7bce-4add-be17-da17fe9b37e1`. |
| Rate limit exceeded (no code) | `429` | >100 calls/60s per IP or >500 calls/60s per subscription | Caller throttling. Do NOT restart pods. |
