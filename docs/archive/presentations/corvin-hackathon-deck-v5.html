Container Logs — 11 KQL Queries

get_container_logs() — Pod stdout/stderr from ContainerLog table
get_pod_inventory() — Pod status, restart counts, images
get_kube_events() — Warning events (OOM, BackOff, scheduling)
get_resource_metrics() — CPU %, memory %, limits (Perf table)
get_oom_kill_events() — OOMKill events with timestamps
get_autoscaler_events() — HPA scaling decisions
get_network_metrics() — TX/RX bytes, error rates
get_health_probe_failures() — Liveness/readiness probe failures

All queries use KQL against Azure Container Insights — no Elastic dependency.

Agentic AI

Not a chatbot — an autonomous agent

Corvin uses GPT-5.1 via Azure AI Foundry's Responses API with chain-of-thought reasoning. It autonomously decides what tools to call, interprets results, and iterates until it reaches a confident diagnosis.

Confidence Scoring

HIGH — Strong evidence correlation, known pattern match
MEDIUM — Probable cause, partial evidence
LOW — Insufficient evidence, needs manual review

Fix strategies are only suggested when confidence meets the policy threshold.

Features — SRE Dashboard

Built for real operators, not demos

🌅 Morning Briefing

Jarvis-style spoken narrative of what happened overnight. Uses Web Speech API for voice TTS. Covers: incidents resolved, pending reviews, trending metrics, recommended actions.

Voice TTS

🎯 Corvin Score

0–100 health gauge per service, calculated from MTTR, confidence distribution, incident frequency, and resolution rate. SVG arc gauge with color-coded thresholds.

🔮 Predictive Alerts

Background monitor runs every 5 minutes. Detects anomalies using trend analysis, seasonal variance, and baseline deviation. Auto-fires investigations before alerts hit.

📈 ROI Dashboard

Quantifies real value: hours saved, cost avoided, MTTR improvement. Calculated from actual investigation data — not projections.

🗺️ Topology Radar

Cross-service dependency visualizer built with XyFlow. Shows: service graph, blast radius scope, upstream/downstream impact paths.

⚡ Alert Simulator

Fire synthetic alerts for training and demos. 4 presets: HPA failure, 5xx spike, auth errors, memory leak. Triggers real investigation pipeline.

📊 DORA Metrics

Deployment frequency, lead time, MTTR, change failure rate — the four pillars of engineering performance, calculated from investigation data.

💫 Platform Pulse

Real-time ticker cycling platform events: recent investigations, approvals, executions, predictive alerts — a live heartbeat of the system.

🌙 3AM Mode

Auto-activates between midnight and 6 AM. Reduces visual noise, increases contrast, disables non-critical widgets. Built for tired eyes.

Features — Investigation + Intelligence

Every incident becomes organizational knowledge

🔬 Investigation Detail

Full RCA view: summary, root cause card, contributing factors, confidence bar, evidence logs (collapsed by default), fix strategy with risk-colored action cards.

🧭 Transparency Trace

Mermaid flowchart showing the AI's reasoning path: Trigger → Evidence collected → Analysis → Root Cause. Shows exactly how the AI reached its conclusion.

💥 Blast Radius Estimator

Estimates: affected services (upstream + downstream), impacted users (based on replicas × 500), revenue risk per minute ($1.25/user/min). Configurable via policy.

✅ Approval + Predicted Outcome

Approve/Reject/Acknowledge via Web UI or Teams. Predicted Outcome Gauge shows before → after impact simulation before you approve.

🧠 Command Center

Natural language chat with the AI agent. Ask anything: "Why is fundapis slow?", "Show me APIM errors for last hour", "Compare this to similar incidents". Tool calls visualized in real time.

📋 Auto Post-Mortems

Blameless post-mortem generated from RCA data + execution timeline. Markdown format with: incident summary, root cause, timeline, action items, lessons learned.

🧬 Incident Memory

Every investigation is stored and searchable. Similar past incidents are automatically injected into future RCA prompts. Knowledge compounds — the AI gets smarter over time.

📖 Runbook Auto-Update

When a new incident pattern is identified, Corvin suggests runbook updates. Runbooks use keyword frontmatter and are matched via catalog.json for automatic injection into prompts.

Features — Integrations & Operations

Five surfaces, one unified workflow

📡 SSE Streaming

Real-time Server-Sent Events. UI shows each stage as it completes: evidence started → evidence complete → RCA thinking → fix strategy → done. No polling.

💬 Teams Bot + Adaptive Cards

Full Bot Framework integration. Sends RCA Adaptive Cards with inline Approve/Reject buttons. Accepts commands: investigate, status, briefing. Blast radius section included.

📧 Email RCA PDFs

Auto-sends RCA PDF via Azure Communication Services. Retry logic with exponential backoff on 429. Recipients configurable per environment.

📖 ADO Wiki + DevOps

Creates investigation pages in Azure DevOps Wiki. Links to work items. Updates work item state on approval/execution. Full audit trail.

📁 SharePoint

Uploads RCA PDFs to SharePoint document libraries. Integrates with existing document management workflows.

🚨 Priority Routing (P1/P2/P3)

P1 (fundsso): 15-min lookback, immediate escalation, SLA countdown. P2 (prod): standard 60-min lookback. P3 (non-prod/predictive): background processing.

⏱️ SLA Countdown

Real-time countdown for P1 incidents. Tracks time remaining before SLA breach. Visual urgency indicator on dashboard.

🏥 War Room

Auto-creates Teams channel for P1 incidents. Aggregates all investigation data in one place. Facilitates real-time collaboration during critical outages.

🔧 Remediation Preview

Before approving a fix, see exactly what will happen: what commands run, what services affected, estimated recovery time. No surprises.

🧪 Testing Strategy

Fake adapter pattern — no unittest.mock.patch. Each test uses real Fake subclasses that override adapter methods. Tests cover: contracts, adapters, orchestration, slices, delivery. All 437 must stay green.

⚙️ Configuration

Fully externalized — YAML files with ${ENV_VAR} expansion. Separated by concern: integrations, models, policies, environments. Zero hardcoded secrets. 10 integration configs.

🔄 Version Discipline

10 versions (V1 → V4.1), each with strict exit criteria. No skipping. Every version requires all tests green + feature validation before moving to next.

🏗️ Module Boundaries

Clean separation: triggers, evidence, enrich, strategy, investigation, execution, delivery, storage, toolsets. Every module is independently testable. Adapters are swappable.
