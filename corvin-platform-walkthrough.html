Architecture

End-to-End Investigation Pipeline

Every investigation follows the same 7-stage pipeline. Data flows from Azure → Python backend → LLM → Postgres → React UI.

① Trigger

Sources: Azure Monitor Alerts, Predictive Monitor, Manual (Web/CLI/Teams)

Backend: corvin/triggers/azure_alert.py parses Common Alert Schema → InvestigationRequest

Key: Auto-classifies priority: P1 fundsso prod · P2 other prod · P3 dev/predictive

② Enrich

Adapters: Log Analytics (KQL), AKS (K8s API), Container Logs, Azure Activity, Elastic

Backend: corvin/enrich/enrichment_service.py runs all adapters in parallel, wraps with try/except (graceful degradation)

Output: EvidenceBundle (APIM logs, pod status, container logs, activity changes, metrics)

③ RCA Generation

Model: azure/responses/gpt-5.1 via LiteLLM (Responses API with reasoning visibility)

Backend: corvin/strategy/rca_generator.py → streams tokens via SSE → parses JSON → RCAOutput

Output: Root cause, contributing factors, confidence (HIGH/MEDIUM/LOW), reasoning

④ Fix Strategy

Model: Same GPT-5.1 call with RCA context

Backend: corvin/strategy/fix_strategy_generator.py → FixStrategyOutput with actions list

Output: Actions (restart pod, rollback, scale), risk levels, estimated impact, justification

⑤ Human Approval

Gate: ApprovalStatus state machine: pending → approved | rejected

Surfaces: Web UI (sticky bar), CLI (approve <id>), Teams Adaptive Card buttons

Audit: Records approved_by + approved_at timestamp in Postgres

⑥ Execute & Verify

Backend: corvin/execution/execution_service.py dispatches to AKS adapter

Actions: RESTART_POD, ROLLBACK_DEPLOYMENT, SCALE_DEPLOYMENT, MANUAL

Output: ExecutionResult with per-action success/failure outcomes

Formula:
  investigations = query(service_name, environment)
  high_conf = count(confidence = 'high')
  avg_mttr = mean(completed_at - created_at)
  
  score = (high_conf / total * 40)
        + (100 - normalized_mttr) * 0.6
  
  // Normalized MTTR: 
  // 0 min → 100 points
  // 45+ min → 0 points

SLA Countdown

  • Shows: "99.9% breach in Stable" or countdown timer
  • % consumed progress bar (green → amber → red)
  • Remaining budget, error rate, burned this month
API: GET /investigations/{id}/sla

Formula:
  target = 99.9% (from policy config)
  budget = monthly_minutes × 60 × (1 - 99.9/100)
         = 43,200 seconds (30 days)
  remaining = budget - downtime_this_month
  error_rate = count(status ≥ 500) / total
  ETA = remaining / error_rate

Source: Postgres + APIM evidence cache

How RCA Is Generated

1. System prompt built from:
   - knowledge/site.md (infra facts)
   - Matched runbooks (catalog.json)
   - Similar past incidents (Postgres)
   - Operator context (description field)

2. Evidence bundle injected as JSON

3. LLM call:
   model: azure/responses/gpt-5.1
   reasoning_effort: medium
   max_tokens: 8192
   response_format: json_object

4. Parsed into RCAOutput:
   - root_cause: string
   - summary: string (detailed)
   - contributing_factors: string[]
   - confidence: HIGH|MEDIUM|LOW
   - confidence_reasoning: string
   - evidence_references: string[]

5. Stored in: rca_outputs table

Blast Radius & Approval Flow

Blast Radius Estimator

  • Affected users: replica_count × 400 users/replica
  • Revenue risk: users × £0.003/user/min
  • Affected services: primary + downstream from APIM logs
  • Severity badge: HIGH or MEDIUM
API: GET /investigations/{id}/blast-radius

Formula (pure calculation, no LLM):
  pods = evidence.aks_context.pods
  replica_count = len(pods)
  
  users = replica_count × 400
  revenue = users × 0.003 (GBP/user/min)
  
  downstream = unique(ApiId from APIM logs)
  
  severity = HIGH if users > 1000
             MEDIUM otherwise

Config: policies/investigation.yaml
  blast_radius_users_per_replica: 400
  blast_radius_revenue_per_user_per_min: 0.003

Key Calculation Formulas

MTTR (Mean Time to Resolve)

AVG(completed_at - created_at) in minutes
from investigation_requests
where completed_at IS NOT NULL

Service Health Score (0–100)

score = (high_conf / total × 40)
      + (100 - mttr_norm) × 0.6

Green ≥ 80 | Amber 50–79 | Red < 50

ROI Metrics

baseline_mttr = 45 min (config)
saved_per = (baseline - actual) / 60 hrs
total_saved = saved_per × incident_count
cost = total_saved × £120/hr

Blast Radius

users = replica_count × 400
revenue = users × £0.003/user/min
severity = HIGH if users > 1000

SLA Countdown

budget = month_sec × (1 - 99.9/100)
remaining = budget - downtime_sec
ETA = remaining / error_rate

Priority Classification

if env ≠ "prod" → P3
if trigger = PREDICTIVE → P3
if service = "fundsso" → P1
else → P2

DORA Change Failure Rate

high_conf = count(confidence='high')
rate = high_conf / total × 100

Trend = "improving" if current_mttr
        < prior_mttr × 0.95

Confidence Threshold Gate

min_confidence = MEDIUM (config)

if rca.confidence < threshold:
  result.confidence_warning = True
  UI shows: "Low confidence RCA —
  manual review recommended"
